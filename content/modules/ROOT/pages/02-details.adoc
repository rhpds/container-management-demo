== Proposed Timing

**Opening (5 minutes):**

* Discuss the container management use case (ISVs and existing containerized workloads)
* Start with the customer outcome: a trusted, consistent platform to deploy and operate containers at scale

**Technical Demo (30-60 minutes):**

* Chapter 1: Console Overview
* Chapter 2: Deploying COTS and existing applications
* Chapter 3: Secure by default
* Chapter 4: Cluster Operations
* Chapter 5: Observability - Logging and Monitoring (optional, adds ~15-20 minutes; treat as time-permitting on a tight schedule)
* Keep each module focused on Know (business context) and Show (live demonstration)

**Closing (5-10 minutes):**

* Reconnect capabilities to the customer problem
* Capture follow-up actions and open questions

== Pre-Demo Checklist

Run through this list before any customer-facing presentation:

* *OpenShift Lightspeed*: Confirm the LLM credentials secret is configured and the Lightspeed Operator reports `Available`. Ask your RHDP environment provider if unsure — this does not self-configure.
* *Storage headroom*: If showing the Crunchy PostgreSQL demo, confirm at least 10 GiB of free storage is available (`Storage → PersistentVolumes`).
* *User for RBAC demo*: Confirm a non-admin user exists in the cluster to use for the RBAC impersonation step. Create one via `Administration → User Management → Users` if needed.
* *Online Boutique deployed*: The Topology view demo in Chapter 1 requires Online Boutique from Chapter 2 to already be running. Deploy it first if doing Chapter 1 standalone.

== Troubleshooting Common Issues

* Console perspective options look different than expected
** Confirm the cluster version and whether OpenShift Virtualization or Advanced Cluster Management is installed
* Operator, Helm, or application install fails
** Verify project selection, catalog filters, and that the Operator or Helm repository is available
* Network policy demonstration does not behave as expected
** Confirm pods and services are in the intended project and labels match the policy selectors
* OpenShift Lightspeed cannot answer questions
** Confirm the Large Language Model (LLM) credentials secret and Lightspeed Operator configuration are complete
* Console stays unavailable for more than ~60 seconds after deleting the `console` Deployment
** Check `oc get clusteroperator console` for a `Progressing` or `Degraded` condition and give the Console Operator another minute; this is expected to be self-limiting
* No custom metrics or alerts appear for your own namespace
** Confirm User Workload Monitoring is enabled (`enableUserWorkload: true` in the `cluster-monitoring-config` ConfigMap)
* `LokiStack` stays in a `Pending` or `Warning` state
** Confirm the `logging-loki-s3` secret values match the MinIO service name, port, and credentials, and that the chosen `storageClassName` exists
* No collector pods appear after applying `ClusterLogForwarder`
** The CLF was likely applied before its prerequisites (service account, RBAC, CA bundle ConfigMap) existed. Delete it with `oc delete clusterlogforwarder instance -n openshift-logging` and reapply after all prerequisites are in place
* Collector pods are `Running` but logs do not appear in `Observe -> Logs`
** Check `oc logs -n openshift-logging -l app.kubernetes.io/name=collector --tail=20` for SSL certificate errors. If present, the `lokistack-gateway-ca-bundle` ConfigMap is missing or not referenced in the CLF `tls.ca` field — follow Step 4 in the logging chapter to create it
* Given the resource footprint of Loki, MinIO, and the Cluster Observability Operator together on a single-node cluster, consider treating Chapter 5's logging and correlation modules as optional if the environment is heavily constrained
