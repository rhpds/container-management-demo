= The quick starts

== Demo flow

=== Know
Frame quick starts as an adoption accelerator that reduces onboarding time and support dependence.

=== Show
Demonstrate discovery and guided execution so stakeholders see how users move from intent to action faster.

In OpenShift, Quick Starts are interactive, step-by-step tutorials built directly into the web console. They are designed to provide "hands-on" learning without forcing the user to leave the platform for external documentation.

Think of them as in-app GPS for your cluster—they don't just tell you what to do; they point to the specific buttons you need to click.

*Where to find them*

Quick Starts are located in two primary places:

* *The Help Menu*: Click the (?) icon in the top header and select *Quick Starts*. This opens a catalog of all available tutorials.
* *The "Add" Page*: In the Topology view, click on Add Page to see the available quick starts.

== Real-Time UI Highlighting

When you start a task (e.g., "Create a Serverless function"), the Quick Start side panel will actually animate or highlight the specific element in the console you need to click next.

*Benefit*: It eliminates the "where is that button?" frustration common with traditional documentation.

== Verification Steps

Each task within a Quick Start ends with a check. The system will ask, "Did your build succeed?" or "Can you see the route?"

* *Success Feedback*: If you click "Yes," you get a satisfying green checkmark.
* *Error Correction**: If you click "No," the quick start provides a "Helpful hint" or a link to common troubleshooting steps specifically for that task.

== Content Variety

The Quick Start catalog has expanded beyond basic "Hello World" apps to include:

* *AI/ML Onboarding*: Deploying Large Language Models (LLMs) or setting up OpenShift AI workbenches.
* *Serverless & Eventing*: Walking through the "Scale to Zero" logic.
* *Operator Demos*: Many Operators now "inject" their own Quick Starts into your cluster upon installation, teaching you how to use that specific tool (e.g., CrunchyDB or Advanced Cluster Management).

== Customizable for Internal Teams

Administrators can create Custom Quick Starts using a simple YAML-based ConsoleQuickStart resource.

*The Use Case*: Platform Engineering teams use this to create "Internal Golden Paths." You can create a quick start that teaches your developers exactly how to deploy an app according to your company's security and naming standards.

== Live Demo: Publishing a Custom Quick Start

This demo applies a custom `ConsoleQuickStart` resource from the web terminal and shows it appearing in the catalog instantly — no restart, no Operator required. It takes about two minutes and closes Chapter 1 with a strong platform story.

=== Step 1 — Apply the custom Quick Start

. Click the *+* (Import YAML) button in the top-right corner of the console.
. Paste the following YAML into the editor and click *Create*:
+
[source,yaml]
----
apiVersion: console.openshift.io/v1
kind: ConsoleQuickStart
metadata:
  name: deploy-grafana-community-operator
spec:
  displayName: "Deploy Grafana from the Ecosystem Catalog"
  description: "Install the Grafana community Operator and deploy a Grafana instance from the OpenShift Software Catalog. No YAML required."
  durationMinutes: 5
  introduction: >
    This quick start shows how to deploy third-party software from the
    OpenShift Ecosystem Catalog using a community Operator.
    No YAML required.
  tasks:
    - title: "Create a project for Grafana"
      description: >
        Navigate to **Home → Projects** and create a new project
        named `grafana-demo`.
      review:
        instructions: "Is the `grafana-demo` project visible in your project list?"
        failedTaskHelp: "Go to Home → Projects → Create Project and enter `grafana-demo` as the name."
      summary:
        success: "Project created."
        failed: "Make sure you are in the Administrator perspective."
    - title: "Install the Grafana Operator"
      description: >
        Go to **Ecosystem → Software Catalog → OperatorHub**, search for
        `Grafana`, select the **Grafana Operator** by Grafana Labs, and install
        it into the `grafana-demo` namespace.
      review:
        instructions: "Does the Grafana Operator show status **Succeeded**?"
        failedTaskHelp: "Wait 30–60 seconds and refresh the Operator details page."
      summary:
        success: "Operator is ready."
        failed: "Check Events in the `grafana-demo` namespace for errors."
    - title: "Create a Grafana instance"
      description: >
        From the Operator details page, click **Create Instance**, switch to
        YAML view, and paste the minimal spec. Click **Create**.
      review:
        instructions: "Is the Grafana pod showing status **Running** in Workloads → Pods?"
        failedTaskHelp: "Open the pod logs and look for startup errors."
      summary:
        success: "Grafana is running."
        failed: "Check that the YAML spec does not include `spec.external`."
----

=== Step 2 — Find it in the catalog

. Click the *?* (Help) icon in the top-right corner of the console.
. Select *Quick Starts*.
. The *Deploy Grafana from the Ecosystem Catalog* quick start appears alongside the Red Hat ones — no page reload needed.

=== Step 3 — Start the quick start

. Click the new quick start to open it.
. Walk through one task to show the side panel highlighting the relevant UI elements in real time.

[TIP]
====
*"A platform team can embed their own institutional knowledge — naming standards, security requirements, approved deployment patterns — directly into the console. Every new user who lands on this cluster gets the same guided path, without reading a wiki or opening a ticket."*
====

[NOTE]
====
The `ConsoleQuickStart` resource is cluster-scoped and takes effect immediately.
To remove it after the demo, navigate to *Administration → CustomResourceDefinitions →
ConsolequickStart → Instances*, find `deploy-grafana-community-operator`, and delete it
from the Actions menu.
====
